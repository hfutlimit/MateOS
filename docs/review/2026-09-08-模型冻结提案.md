## 2. 我保留意见的三处

### 反驳 1：Invariant「Execution cannot exist without WorkItem」——不成立

**理由**：
1. 它与 PRD §3.2 的明确设计相反：`@backend 看下代码` 这类请求不是工单。
2. 它与"AI 是 teammate 不是 employee"定位自相矛盾。队友会做很多不进工单的事——问一句、看一眼、帮评审。强制挂 WorkItem 等于把 MateOS 退化成"带 AI 的工单系统"。
3. 它会污染数据：为每个临时提问自动建 WorkItem，Work 页会被垃圾记录淹没。

**修订后的表述**：
> Execution 是**运维事实源**，不是业务实体。它可以独立存在；独立 Execution 只出现在 Channel 与 Execution 详情页，**不出现在 Work 页**。

即：约束落在**视图**上，不落在数据模型上。这样既保住"用户在 Work 页只看到一件事"，又不牺牲 teammate 语义。

同理，Execution 也不该被称为"Execution History"——它有独立 lifecycle、可取消、可重试、占 slot、产生 cost。降级成 history 会丢掉这些能力。

### 反驳 2：Day1 模型里删掉 Project —— 危险

`Workspace / Channel / Topic / WorkItem / Execution / Memory` 这版没有 Project。但 Project 当前承担四个不可替代的职责：

| 职责 | 依赖方 |
| --- | --- |
| Memory 作用域（Project Shared Memory） | E5 |
| WorkItem 归属边界 | E8 |
| Provider binding 挂载点 | E8 / E9 |
| 成员可见范围 | E1 / E6 |

**建议**：改名可以（Project → Workspace），**删除不行**。若改名，必须在文档里显式列出上述 4 个职责的承接者，否则 E5/E8/E9 全部失去作用域。

### 反驳 3：「Topic contains WorkItems」——应为引用而非拥有

"contains" 隐含所有权，会把我们刚解决的 6 容器问题换个名字带回来：一个 WorkItem 会在多个 Topic 里被讨论，谁拥有它？

**建议**：Topic **引用** WorkItem（N:M），WorkItem **归属** Project。Topic 不承载业务状态（04 文档 §2.1 已这么写，P5b 原型违反了，改原型）。

## 4. 文档治理（吸收 ADR 建议，但加一条防污染规则）

```
docs/
  architecture.md        ← 永远是当前设计，无变更历史
  spec/invariants.md     ← 可执行的不变量，CI 可扫
  decisions/ADR-000x.md  ← 只在"决策被推翻"时写
```

**关键防污染规则**：ADR 只在**已有决策被推翻**时新增，日常修订直接改主文档。
否则 ADR 目录会变成第二个 changelog——以本项目的修订密度，这条不写明的话三个月内必炸。

配套 CI：禁用词扫描 `AgentBoard` / `can_execute` / `can_review` / `REQUEST` / `active_slots` / `work_item_projections`。

## 9. 补充：「第一个 10 分钟」对架构的三个硬约束

认同这条比架构问题更关键，但它的定位应是**架构的验收标准**，不是独立于架构之外的工作项。它直接否定当前三处设计：

| 当前设计 | 对 10 分钟体验的破坏 |
| --- | --- |
| `agents.credential_id NOT NULL` | 用户第一步必须去申请 OpenAI/Anthropic key → 10 分钟变成"10 分钟 + 注册第三方账号" |
| WorkItem 四级类型 + Provider 选择 | 首次创建要选类型、选 Provider、配 status mapping |
| `execute_code` 默认 DENY | "完成一个 WorkItem"到底交付什么？目前无定义 |

**补充一条双方都没提的**：10 分钟体验必须定义**退出时留下什么资产**——否则是 demo 不是产品。建议锚定为：
> 1 条已通过人审的 Memory + 1 个已完成的 WorkItem + 1 个可再次 @ 的 Agent。

这三个资产的留存率，才是 MVP 该测的指标。

**另需处理的冲突**：Inbox 作为首页 + 空 Inbox 的第一印象互相矛盾。解法——first-run 时 Inbox 渲染成引导卡（"3 步启动你的 AI 团队"），有内容后自动退化为常规 Inbox。
